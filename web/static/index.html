About this report Metric definitions and data scope

Customer identities

Each entry is one canonical customer ID. Unmatched and ambiguous identities remain separate, so this is not a verified count of people.

Accounts and balances

Active accounts count OPEN or ACTIVE statuses. Balance totals include all loaded accounts, regardless of status. Credit and loan balances are combined without netting against deposits.

Consent and activity

Consent is specifically CDR_DATA_SHARING. A missing record is Unknown, not approval. Latest activity includes transactions, loan repayments and CRM interactions. Source timestamps have no timezone.

About this report Thresholds and data scope

One customer, one day

One row per canonical customer ID per transaction date. Only transaction facts are included; repayments and CRM interactions are excluded.

Review rule

At least 3 transactions OR a largest absolute amount of at least A$1,500 triggers REVIEW. Gross value sums absolute amounts; deposits and withdrawals both contribute positive amounts.

Filtered results

Summary values, chart and filtered CSV use every matching row, across all pages. Full report exports ignore filters. Select a day for the underlying transactions. A review flag is not a finding of fraud.

About this report Rules, priority and missing values

First matching rule wins

The SQL checks loan review, card balance review, then credit card review. One suggestion is returned per identity with sufficient identity and account data.

Active products in loaded data

OPEN and ACTIVE accounts determine current holdings. Closed accounts do not block a review. Missing account data remains Unknown and requires review.

Review candidates

Rules produce human-review candidates, not credit decisions, proof of financial difficulty or marketing permission. CDR consent is not marketing approval. Export filtered follows the current filters across all pages; Export all retrieves the full report.
